1 · The Mental Model

Model vs. Coding Harness vs. Meta-Harness

When people talk about “AI coding agents,” three completely different layers get blurred together. Understanding where each stops is the whole story of engsys.

Layer 1 · The Brain

The Model

Raw reasoning and code generation. Brilliant in a single turn, but stateless — it wakes up with amnesia, has no terminal or filesystem on its own, and knows nothing about your team’s engineering process.

Examples: Claude Opus 4.8 & Sonnet · GPT / Codex · Gemini · Grok · DeepSeek
Layer 2 · The Workbench

The Coding Harness

Wraps a model in an interactive CLI or IDE runtime with bash execution, file editing, subagents, MCP servers, and lifecycle hooks. Great for driving one assistant — but out of the box it has no org chart, no role boundaries, and no cross-PR memory.

Supported Harnesses: Claude Code (claude) · GitHub Copilot CLI (copilot) · Google Antigravity (agy)
Layer 3 · The Engineering Org

The Meta-Harness (engsys)

Sits above your coding harness and across models. Defines who does the work (15 personas), which stack rules apply (24 packs), how work moves (spec → worktree → review → merge), and what the team remembers — then compiles that system into whichever harness you run.

One config: engsys.config.yaml → materializes into Claude Code, Copilot CLI, or Antigravity

2 · The Core Design (3-Part File Taxonomy)

Persona, capability pack, project facts

Inside engsys, a three-part file taxonomy keeps your setup portable across every repository: who does the work, which stack they target, and what is true about this repo — kept ruthlessly separate so you swap packs instead of rewriting prompts.

Persona — who

Stable everywhere

Voice, first-principles diagnostic checklists, least-privilege tool allowlists, and handback schemas that never change from repo to repo.

Capability — which stack

24 detachable packs

Adapting to a repo means selecting aws vs azure or typescript vs swift in YAML — never hand-editing agent prose. Mixed stacks compose cleanly.

Project facts — this repo

Generated + naturalized

Services, build commands, and house invariants rendered into your harness instructions (CLAUDE.md / GEMINI.md) and filled once via /naturalize.

MelvinCloud architect — same person, every cloud
Pick the project’s cloud → he loads the matching capability pack. His persona file never changes.

Fifteen specialists, one install

4 · How Work Moves

Adaptive Spec to Closeout, on rails

Workflows route work through the specialists in order: risk-adaptive specs (/design-change), isolated worktree implementation, cross-family code & security review, preflighted merge, and automated lesson harvesting.

5 · Compounding Agentic Memory

It gets smarter every PR — without prompt-injection risk

Dumping raw GitHub comments into an agent’s prompt wastes context and invites prompt injection. engsys separates trusted instructions from untrusted repo evidence and compiles a targeted ≤ 2 KB brief at every SubagentStart.

Class A · Trusted Instructions

Curated Lessons (origin/HEAD)

51 bundled cross-project lessons plus your repo’s local lessons, each tagged with YAML frontmatter (stacks, paths, roles, security: true). Loaded strictly from reviewed git refs — never unreviewed working-tree edits.

Guarantee: security: true lessons are always injected first and never dropped by token budgets.
Class B · Historical Repo Evidence

Git Ref Store (refs/engsys/memory/*)

Merged PR outcomes, review findings, and issue history synced via memory-sync into an append-only custom Git ref with CAS retry, mandatory secret scanning, bot databaseId verification, and spoofing quarantine.

Safety: Only compact 1-line pointers are pushed at startup; full text is fetched on demand inside an untrusted envelope.
Runtime · Subagent Injection

SQLite FTS5 + PreToolUse Stash

When an orchestrator dispatches a subagent, PreToolUse stashes the task prompt and target file paths. At SubagentStart, memory-brief scores Class A lessons (BM25 + path/role) and Class B pointers in milliseconds.

Loop closure: At /project-closeout, harvest-findings clusters recurring PR review comments into new Class A lesson drafts.

When you want the team to keep shipping while you sleep

8 · Install & Use

Deploy by hand — or hand DEPLOY.md to your agent

A deterministic zero-dependency Node CLI writes the folders and merges settings faithfully. Your model only fills in project facts afterward via /naturalize.

Fastest path: let your coding harness deploy Stage 1 for you
Paste this prompt into Claude Code, GitHub Copilot CLI, or Google Antigravity:
Read https://raw.githubusercontent.com/eric-sabe/engsys/main/DEPLOY.md and deploy Stage 1 into this repository.
Get the CLI

Install globally from npm — or git clone https://github.com/eric-sabe/engsys. Zero-dependency Node (≥20.11); runs identically on macOS, Linux, and Windows.

npm install -g engsys
Scaffold engsys.config.yaml

Pick your coding harness (claude | copilot | antigravity | all), stack packs (cloud / iac / lang / platform / db), and optional specialists.

engsys init
Materialize into your project

Writes your harness directories, renders instructions + settings, and seeds the 51-lesson library. Existing setup? It adopts and backs it up so engsys uninstall can restore byte-for-byte.

engsys install --into .
Naturalize project facts

Open the repo in your harness and run /naturalize. It fills the fenced PROJECT-FACTS region and project-brief-overlay.md — the one model-driven step.

/naturalize
Verify & evolve

Check drift against the lockfile, enable external review providers (codex,grok,deepseek), update packs, or roll back cleanly.

engsys verify --into .  ·  engsys update --into .  ·  engsys uninstall --into .
